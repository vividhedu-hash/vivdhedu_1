### Data honesty

`mapSupabaseRowToRecord` and `ROIBreakdown` substituted constants for missing
measurements — `1_200_000` median salary, `88%` placement, `120` seats, `140`
companies, `78/82/85/88` sub-scores. **19 of 73 active programs** have no
`placement_data` row, so a quarter of the catalogue presented invented figures
as measured.

All constants are now `null`; types widened to `number | null` so the compiler
enforces it; UI renders explicit no-data states; ROI reweights over measured
inputs only. `TestNoFabricatedData` blocks regressions.

### Engineering

The backend **could not be installed** on a clean machine:

- `crawl4ai==0.4.3` was never published to PyPI (only `b1`/`b2`/`b3`), and
  every crawl4ai release needs `pydantic>=2.10` against a pinned `2.8.2`.
- `pytest` was in no manifest at all.

So there was no way to run tests, which is why there were none. Fixed both.

Tests were also **querying the production database** from CI —
`test_college_roi_index_from_database` asserted on live `roi_scores`. Now
sandboxed via `tests/conftest.py`.

New CI: `backend-tests` (50), `secret-scan`, `rls-audit`. `rls-audit` was
verified against `USING (true)` / `USING true` / `WITH CHECK (true)` /
`using(TRUE)` — all caught, no false positive.

Repo hygiene: dropped AI-partnership ceremony files, untracked ~12MB of
generated docs. **18.4MB → 3.6MB.** `.cursorrules` rewritten as real rules.

## Known limitation

`next.config.mjs` sets `ignoreBuildErrors` and `ignoreDuringBuilds` to `true`.
A type or lint error will not fail `npm run build` — Vercel deploys regardless.
`type-check` in CI is the only real gate. Worth turning off.
